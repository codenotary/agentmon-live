# AgentMon Live web view: implementation plan (branch `browser-screen`, 0.24.0)

## Context

The terminal pane has no room for charts, sortable tables, a searchable log or a view across sessions. The doc "AgentMon Live Web View — Implementation Plan" (claude.ai/artifact/A1cm5E6ACF27unzheGp7pi) specifies a read-only browser page on loopback. It left one item open: the real theme from `../agentmon-teams`. This plan closes that item and fixes four assumptions in the doc that the code and the engine API contradict.

Branch `browser-screen` exists, off `main`, with no commits yet.

## Tasks

Each ends green on the checks in Verification, with one commit. TDD: write the test, see it fail, implement.

### 1. Server (`server/web.mjs`, `tests/web/server.test.mjs`)

Plain `node:http`, no dependencies. Three modes:

- `web.mjs ensure <startPort>`: for each of 20 ports, `GET /health`. Answer `{name:'agentmon-live'}`: print `{"port":N}`, exit 0. Refused: spawn self as `serve N` with `detached:true, stdio:'ignore'`, `unref()`, poll health for 3 s, then the same check (a lost race lands on the winner's server). Other answer: next port. None: exit 1.
- `web.mjs serve <port>`: binds `127.0.0.1`. Reads `app.html` and fonts into memory at start, so a plugin update that removes the old folder does not break a running server.
- `web.mjs open <url>`: `cmd /c start "" <url>`, `open`, or `xdg-open` by `process.platform`. Accept only `http://127.0.0.1:` URLs.

Routes: `GET /`, `GET /fonts/:name` (fixed list), `GET /health`, `GET /events` (SSE; all snapshots on connect, then each change, `removed` events, 15 s comment keep-alive), `POST /state/:id`, `DELETE /state/:id`.

Security at this trust boundary:
- Reject any request whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding).
- Reject POST and DELETE that carry an `Origin` header or lack `content-type: application/json` (a web page cannot post a snapshot).
- Validate `:id` against `^[\w-]{1,80}$`; parse the JSON; 413 over 1 MB.
- Send `Content-Security-Policy: default-src 'self'; script-src 'unsafe-inline'; style-src 'unsafe-inline'`, and `X-Content-Type-Options: nosniff`. No CORS headers.

Life: a session with no POST for 90 s drops (a crash sends no DELETE). The server exits 60 s after its last session leaves.

Tests, with `node --test`: ensure prints the port; second ensure finds the same server; port taken by a foreign server moves up; POST then `/events` replays; DELETE sends `removed`; 413; bad Host 403; POST with Origin 403; TTL and idle exit (timings via env overrides `AGENTMON_WEB_TTL_MS`, `AGENTMON_WEB_IDLE_MS`).

### 2. Snapshot and publisher (`hooks/web.ts`, `types/index.d.ts`, `tests/web.test.ts`)

Add `WebSnapshot` to the types: `{ v: 1, session: {id, cwd, branch, startedAt}, main, focus, usage, turns: {startedAt, wallMs, buckets}[], session totals, calls, agents, checks, files, log, tasks, skills, insights, learned, advisor, labels, lang }`.

Top-level functions in `hooks/web.ts` (`$` rule in `CLAUDE.md`):
- `toSnapshot(parts)`: pure; maps what was read to the contract. Own unit test, and the source of `tests/fixtures/snapshot.json`.
- `startWeb($, cwd)`: if `cfg.web`, `$.process.run(['node', `${$.plugin.root}/server/web.mjs`, 'ensure', port])`, parse the port, set `cfg.webUrl`, `$.ui.invalidate('ui.render')`, start the loop, open once if `webOpenOnStart`. Any failure: one debug line, `cfg.webUrl` stays undefined.
- `publishLoop($)`: guarded by a module flag. Every 500 ms read atoms, `$.session.usage()`, `$.agent.list()`, `liveTurn`; serialize; POST when changed or 30 s since the last post. Failed POST: debug line, re-run `ensure` at most once per 60 s.
- `stopWeb($)`: `DELETE`, in `session.end`, best effort (TTL covers the rest).

The turn ring is a module variable: push `ins.last` when its `startedAt` is new. `// shortcut: the turn ring restarts on a module reload, keep it in the store when people ask for history across reloads.`

Focus: move the input assembly at `hooks/render.tsx:183` to a helper in `insights.ts`, so the pane and the snapshot read the same list.

Register: `void startWeb($, cwd)` inside the existing `$.clock.after(0, ...)` in `session.start` (`hooks/register.tsx:313`). `on('session.end', ...)` wrapped with `failOpen`.

Tests with stubbed `process.run`, `http.fetch` and `mock.clock`: one POST for a burst; no POST when unchanged; heartbeat at 30 s; no spawn with `web: off`; refused `process.run` leaves the pane drawn and no URL. Existing tests must stay green: with no `process.run` hook beneath, the loop must not start. Check first that `clock.settle()` does not spin on a repeating timer.

2. Second session: one server, and the picker shows both. End the first: the second keeps updating.

7. `node scripts/web-shot.mjs`: compare light, dark and 390 px against the running AgentMon Start dashboard.
8. Desktop app or VS Code, where `$.process` is documented "CLI only": refused cleanly, no button.

## Risks left

- Loopback with no auth (the doc's decision): another local user on a shared machine can read `/events`, which holds commands, paths and costs (secrets masked). Fine on a single-user laptop, not on a shared host. The token in the doc's "later" list fixes it.
- A daemon left from an older plugin version serves its old page until it idles out; the `v` banner covers a contract change. `// shortcut:` comment in `web.mjs`.
- The tokens are copied, so they can drift from `agentmon-teams`. `agentmon-teams` is BSL and this plugin is Apache-2.0: colour values and OFL fonts only, no components copied. Confirm this is fine for Codenotary.
