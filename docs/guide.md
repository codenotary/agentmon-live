# AgentMon Live guide

Everything the pane shows, every option, and how learning and the self benchmark work. For install and the short tour, see the [README](../README.md).

## What it shows

Top to bottom, in the order you need it:

- **Header**: the models, the done gate, and the version. When a newer AgentMon Live release is out, `update` (`u`) sits next to the version and drafts the two update commands, and `changelog` (`l`) folds out that release's notes. The mod asks GitHub's releases API at session start: a newer release it found is kept a day, anything else an hour, and an install or update since the last look asks again at once; never while `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set.
- **Focus** (always on top, in every view): first what needs you (a tool call waiting for your approval, three failed calls in a row, a failed check, a subagent that failed or reported failing tests, a subagent waiting), then what is worth a look, ranked by importance: a call running far longer than that tool usually takes, a subagent quiet for minutes, the same call failing again and again, the same error behind different calls (its first line, with numbers and paths taken out, matched across calls), context near compaction or one tool result that flooded it, a file read over and over or edited over and over, docs read and code changed in one turn that was not a refactor (`i` drafts: where docs and code disagree, follow the code and list each inconsistency), approvals holding up the turn (with the calls asked most, to turn into allow rules), a low prompt-cache hit rate over this turn's requests (from the second one on), focus jumping between many parts of the project, one tool category eating most of the turn, MCP tool schemas taking a large slice of the window, a plan window (5h, 7d) filling faster than it resets, a large session (150k+ tokens) idle past its one-hour prompt cache, two prompts in a row that correct the last change (`i` drafts a summary to start over with `/clear`), a turn in parts of the project a large session had not touched (start the next unrelated task with `/clear`), a custom subagent on Opus or Fable that only read or searched (`model: haiku` in its definition costs less), a base branch that moved, in red when it changed files the session edited (`i` drafts the rebase), a secret in plain text in the project's `.claude/settings.local.json` or `.claude/settings.json` (an API key in a command that "don't ask again" saved as an allow rule, or in `env`), in red when git does not ignore the file and yellow when it does, shown masked (`i` drafts the cleanup; the mod changes nothing itself, and a short password without a telling shape is not seen), a turn with far more tool calls than this project's turns usually take (see Learning), and peak hours (weekdays 05:00–11:00 Pacific), when limits may be used up faster. Three show at once (`d` shows all); `i` drafts a question about the first one that has one, `x` puts them away. When nothing needs a look it is one line: where the last turn's time went.
- **Running now:** each tool call in flight, with who runs it and for how long; when idle, the last call. Running and waiting subagents sit here as cards. In the calm layout, past four running subagents the first four stay cards and `a` folds the rest out as one line each; this part always keeps three rows, each cut to one line, so the sections below do not jump.
- **Insights:** where the time went, this turn and over the session, as one bar: the model streaming, each tool category (parallel calls share the time), you (calls waiting on an approval) and idle; the slowest calls (approval waits left out), each with **investigate**, which drafts why it was slow and how to speed it up (`i` when Focus has nothing to ask; in calm, where Insights is hidden, `investigate` sits on Focus's one line); the main context per model request as a sparkline, its growth in the last turn, the prompt-cache hit rate and the biggest tool results (≈ characters / 4); tokens in, cached and out, and the subagents' share; how often the main loop moved between parts of the project this turn, and the files it re-read or re-edited most. With details on, the window's breakdown by category (from a local estimate, no extra request), MCP schema and CLAUDE.md tokens, and model or effort switches.
- **Done gate:** when Claude is about to stop after real work (3 or more tool calls, an edit, or a subagent), it checks what the session recorded: a test, lint, typecheck or build that failed this turn (not one that already failed at the prompt or before the turn's first code edit), one that ran before the last edit, an answer that says the tests pass or the build succeeds when no check of that kind ran after the last code edit (edits outside the project folder, such as a scratch file in `/tmp`, do not count; edits made through the shell, such as `sed -i`, do: the gate compares `git status` and `git diff HEAD` at the start and end of the turn, docs left out), a test run that ran no tests (a filter that matched nothing, even with exit 0), a test command that ran fewer tests or skipped more after the last edit than the same command's last run before that edit (a deleted test file, an added `.skip`), an edited package no test run after the edit reached (see [Test targets](#test-targets)), todo items still open, a subagent that reported failing tests. Anything found goes back to Claude, once per prompt, as a Stop hook block: "Before you report done, this looks unfinished: … Finish it, or say plainly why not." Only when the facts show nothing does Fable, a second model that never writes code, judge two things: does the final answer address every part of the request, and did the work add a feature, option or abstraction you did not ask for? Work the request needs (tests, docs, fixes it depends on) does not count as extra, and Fable skips the second question when the prompt only refers to earlier talk ("do it", "yes"), since it sees only the latest prompt. It sees the changed files, the tool calls and the final answer but no diff, so an extra inside an edited file shows only if the answer names it. The box reads `✓ nothing left open at the last stop`, `↩ sent back to Claude:` with the gaps, or `⚠ stopped with this left open:` when Claude stopped again with gaps; `f` then drafts the same reason as a prompt. Each result names when it came and the request it is about (`↳ 2 min ago · "fix the parser"`) and leaves when your next turn starts. Below it, `earlier this session:` lists the session's earlier results, newest first: mark, when, the request and the first gap; three show, `d` shows all, and `/agentmon clear` empties the list. It does not block while subagents started this turn run (a background subagent from an earlier turn does not hold it), after another Stop hook already sent the turn back, or when off. **Check now** (`c`, or `/agentmon check`) runs the same check and only shows it; while a turn runs, it waits for the turn's answer. Its state reads checking, off, checks only, unavailable (Fable failed; Claude then stops as usual, and Fable is not asked again for five minutes) or budget used, with Fable's call count and tokens.
- **Changes and verification:** files edited and read (successful calls only), and the last test, lint, typecheck and build command with its outcome: ok, failed, or unknown when a pipe, a `||`, a later command after `;` or a denial hides the exit status (with several checks in one such command, the output decides only the last; the others read unknown). When a command with several kinds of check fails, such as `tsc && npm test`, the last check reads failed, since the command did fail, and the ones before it read unknown: `&&` may have stopped at any of them. A test summary in the output still decides for tests that ran last. A check sent to the background (`run_in_background`, or a trailing `&`) stays running until the next run of its kind, because the call returns before it ends: it backs no "tests pass" and covers no edit. A test row also shows how many tests ran and were skipped, when the runner's summary says (jest, vitest, node, bun, mocha, pytest, cargo; go gives no counts), and the directory it ran in when that is not the project root. A check run before a later edit is marked stale. Test files edited are listed there too, with assertions removed or changed and skips added, and the changed lines under them (`d` shows more). A passing run over the edited test after an edit that removed or changed an assertion, or added a skip, also raises a Focus item (a run in another package does not count), because a green run says nothing about a test edited to pass. `i` drafts a question with those lines that asks Claude to justify each one. Only adding assertions stays quiet. The list stays across turns until `x` puts it away. It sends nothing back, because some test updates are right: a run with fewer tests sends the turn back only when that turn edited no test file. Edits made through a shell command are not seen.
- **Usage:** context, cost and rate limits with their reset times; `unavailable` where the session does not report a value.
- **History** (folds with `h`): main session, tool counts per category with errors and calls in the last minute, the git / shell / MCP detail tabs (`g` `s` `m`, a click, or `/agentmon git|shell|mcp`), finished subagent cards and the session log.
- **Hide** (the `◂ hide` button in the header, or `p` after a click on the pane) closes the pane and leaves one button above the prompt, `▸ AgentMon Live`. Click it, or press `Ctrl+X Tab` then `p`, to bring the pane back. `/agentmon` also brings it back, and is the way on VS Code and mobile, which have no such row. The close mark, or `Ctrl+X X` after a click on the pane, does the same as hide. The pane stays closed after `/clear`, and a new session starts with it open. On a terminal too narrow for the pane to open by itself, the same button is there to open it.
- **Details** (`d`) shows cut-off tasks, commands and error texts whole. It brings back no section; `v` (classic) does.
- **Layout** (`v`, or the `◐ calm` / `◐ classic` switch in the header) switches between calm and classic. Calm (the default) leaves out Insights and Skills, and Usage unless it needs you (context or a rate limit running high), keeps the other sections in the order above (only one that needs you, such as a failed check or a gap the done gate found, moves to the top), shows a breathing dot instead of the spinner, and moves running times in 5 s steps (`<5 s` at first). Classic shows every section, moves sections active in the last two minutes up, newest first, and shows up to six subagent cards before listing them one line each.

Subagent test results are *reported* from the agent's final answer (a failure wins over a pass). Running and waiting subagents are always kept; the last 60 finished ones stay. The status line counts git commands as `git [n]`.

Languages: English (default), German, French, Spanish, Chinese and Japanese.

## Use

| Command | Does |
| --- | --- |
| `/agentmon` | Opens the pane |
| `/agentmon advisor` | Turns the done gate on or off |
| `/agentmon check` | Runs the done gate's check now, without sending anything |
| `/agentmon git`, `shell`, `mcp` | Shows that detail tab |
| `/agentmon details` | Shows cut-off texts whole (`d` in the pane) |
| `/agentmon open` | Opens the web view in your browser (`o` in the pane; see Web view) |
| `/agentmon learn [dir]` | Learns from this project's past transcripts (or the `.jsonl` files in `dir`) |
| `/agentmon memory` | Checks the memory and instruction files now and lists what it found |
| `/agentmon bench` | Compares this project's sessions with and without the mod, and the last 7 days |
| `/agentmon debug` | Prints the path of this session's debug log (see Debug log) |
| `/agentmon clear` | Resets counters, finished cards, log and the done gate's results; running subagents stay. The word for clear in each language works too: `leeren`, `vider`, `limpiar`, `清空`, `クリア` |

The pane opens by itself at session start when the terminal is wide enough.

## Options

Installing asks nothing. Ask Claude in chat ("hide the usage box", "switch AgentMon to German"), or edit `pluginConfigs` in `~/.claude/settings.json` (or `$CLAUDE_CONFIG_DIR/settings.json`). The bundled `agentmon-config` skill tells Claude where the options live. An edit by Claude applies at once, your own at the next prompt; `debugLog`, `gitPollMinutes` and `gitFetch` apply at the next session. The options do not show in `/config`, and project, `--settings` and managed settings are not read. `language` not set follows the terminal: `LC_ALL`, then `LC_MESSAGES`, then `LANG`; a locale the mod has no language for gives English.

| Option | Values | Default |
| --- | --- | --- |
| `language` | `en`, `de`, `fr`, `es`, `zh`, `ja` | the terminal's, else `en` |
| `advisorModel` | any model id | `claude-fable-5-1` |
| `advisorMode` | `all` (done gate with Fable's coverage check), `gate` (done gate from recorded facts only, no model), `off`; `plan` is read as `gate` | `all` |
| `advisorBudget` | most Fable calls per session; `0` for no limit | `30` |
| `sizeLimit` | bytes a maintained source file may reach before Focus suggests splitting it; `0` turns the guide off | `20000` |
| `sizeExclude` | comma-separated globs the size guide skips, on top of the built-in ones | empty |
| `refreshRate` | seconds between pane redraws: `5`, `15`, `30`, `60`; `live` redraws on every change. Keys and new urgent items (an approval, a failed check or subagent) redraw at once; an idle pane stops redrawing | `live` |
| `layout` | `calm` (fewer sections, quiet animation) or `classic` (see Layout above); `v` switches in the pane | `calm` |
| `hiddenSections` | comma-separated dashboard sections to hide: `tasks`, `insights`, `skills`, `advisor`, `changes`, `usage` | empty |
| `learning` | `on` keeps what each session of a project shows (below); `off` keeps nothing | `on` |
| `debugLog` | `on` writes each session's events to a debug log (below); `off` writes none | `on` |
| `gitPollMinutes` | minutes between checks of the base branch (below); `0` turns the check off | `5` |
| `gitFetch` | `true` runs `git fetch` for the base branch before each check; `false` compares against your last fetch | `false` |
| `web` | `on` runs the local web view (below); `off` starts no process and shows no button | `on` |
| `webPort` | first port to try, 1024 to 65535; a port something else holds moves it up by one, 20 tries at most | `47311` |
| `webOpenOnStart` | `true` opens the browser once per session at its start | `false` |
| `webToken` | `on` lets only your account read and post sessions on the web view's port (below); `off` lets any local process | `on` |

### Web view

The same session in a browser, with the room a terminal lacks. The top bar shows the mod's version and commit, as the pane's header does. Open it with `o`, `/agentmon open`, or the link in the pane's header. It follows your language and starts in the dark theme; its button switches to your system's setting or to light.

- **Top bar:** beside the session, the last done gate result of this prompt, with its reason on hover.
- **Keys:** `j` and `k` move across table rows, `g` then `o`, `c`, `v`, `a`, `f` or `l` goes to a section, `/` to the log's search.
- **Tool calls:** filter by tool as well as agent, with buttons or, past eight tools or agents, a dropdown each, and an MCP server's tools share one button; a failed row shows the first line of its error. **Insights** also lists approvals asked more than once. **Verification** counts files changed after the last passing test run. **Session log** runs your prompts, Claude's answers, tool calls, subagents, test reports, compaction, done gate results and a resumed, cleared or forked start in one stream. An answer row shows the answer's first line at the end of its turn; click it to read the answer whole (up to 1,500 characters, secrets masked). Equal calls in a row merge into ×n, and a subagent's start and end into one row with its duration. That row also holds the subagent's calls, with their count and how many failed; click it to unfold them. A search or the failures button lists the calls themselves. A failed call keeps its own red row. Buttons filter to failures, your prompts or subagents, each with its count. Bars above the list show activity over time, red where a call failed, and a click goes there. Click a call for its details. **Files** shows paths inside the project, and a file in an agent's worktree as the project file it stands for. The ten latest edits of each group show, the rest behind Show all. It groups edited files by the last test run: not tested since the last passing run (or, in amber, no passing run yet; in red, the last run failed), then edited before the passing run, which does not prove a test covers them. Each row shows how often the file was edited and when it last changed. Files only read follow, most read first, two until you open the list.
- **Agent flow:** folded while no subagent runs, and it opens by itself when one starts; the arrow opens or folds it by hand until the next change. One lane for the main session and one per subagent, a dot per call, with curves for who started whom and when an agent handed back, and a dashed curve for each message one agent sent another (SendMessage to an agent the chart has a lane for). Failed calls are red, a call waiting for you has an amber ring, and dashed lines mark the last test, lint, typecheck and build runs. Drag on the strip on top to choose a time: it opens on the last two minutes with activity, 1 min, 5 min and 15 min show that much of the present, and Follow keeps it at the present. The strip reaches back as far as the last 500 calls and the session start. Every subagent has its own lane, numbered when several share a task's words, and finished lanes can be hidden. A lane shows only while its agent runs or did something in the chosen time; a line under the chart counts the others. The chart glides along, takes new data every 3 seconds, and holds still while the pointer is on it. With reduced motion on, it moves in steps. Click a dot for its details, or a mark with a number for the list of its calls, and a name to open that agent and filter Tool calls to it. With the chart focused, arrows move the time, `[` and `]` shrink and grow it, Home goes to the start and End follows.
- **Turn waterfall:** every tool call in the time chosen in the agent flow, in the order it started, as bars by how long each took, with each subagent's calls nested under it. A subagent goes by its description here and everywhere on the page, without a prefix several share; hover for the whole of it. The slowest call is marked, failures are red, running calls are striped, and a call waiting for approval says so. Gaps are time the model spent thinking. Click a call to see its details.
- **Lost signal:** the logs and panels stay, so you can see where things stopped, and nothing reads as current without fresh data. If the connection to the server drops or hangs (35 seconds with no event), the top bar says `disconnected` with a banner, and the page keeps trying. A session that has posted nothing for 45 seconds, such as a killed terminal, reads `no signal` with a banner. Either way the bar or banner says when the last update came, clocks stand at that update, busy marks stop and fade, and panels say `was running`, `was waiting` and `Running at last update`. In the session switch these sessions get a hollow dot, and the tab title starts with `⚠`, so you see it from another tab. A silent session stays on the page past the server's 90 seconds until you press **Dismiss** or reload. A session that ends normally leaves the page at once.
- **Help:** every widget has a small `i` beside its title. Hover it for what the widget shows, or click it to keep the text open.
- **Navigation:** one page of sections, each with a heading that folds it, and a rail on the right that moves to each and opens it. The page remembers what you folded in this browser, and a folded section still shows its count. The sections: Overview (instruments, agent flow, waterfall, where each turn went, events, running calls), Tool calls (a table of the last 500 calls of every tool, insights), Verification (lights, test files edited with their changed lines, and tasks), Subagents, Files and Session log. The rail marks the section you are reading. Each section has its own link, and the browser's back button works. The rail shows how many events are open, how many calls run and how many subagents the session has. On a phone it is a strip across the top.
- **Events:** what needs you, such as a waiting approval or a failed test, as a timeline. An item that goes away stays there, marked cleared with its time. This browser keeps the history of the last ten sessions, so a reload keeps it; another browser starts when it opens the page. A new urgent item changes the tab's title, so you see it from another tab. Open items that need you sit on top under Needs attention and the rest follows newest first. An approval is amber, with ⏸ in the tab title; a failure is red, with ✖. Buttons above the list show one kind at a time, each with its count: failures, waiting (approvals, waiting or quiet subagents, slow calls), context, memory files, and other.
- **Instruments:** dials for context (click it to see what fills it, tokens against the window below the name), the 5-hour and 7-day quotas (shown once a value exists; a tick marks an even pace up to the reset, and the note says on pace or ahead of pace) and the main session's cache hits (green when high). Rulers for session cost and turns, each against the median of this project's earlier sessions once three exist (a tick marks that typical value; until then against a fixed guide of $10 and 20 turns, in neutral colour), and for time blocked on you as a share of session time. A bar splits tokens in and out. The colour says good, watch or bad. Pins move on a change and shake slightly while the page is connected; that movement is decoration, the numbers are exact. The shaking stops when the connection drops and under the reduced-motion setting. The session cost keeps its trend since you opened the page.
- **Subagents:** a table with one row per subagent, so thirty fit on a screen: what it does, type and model (named once beside the title when most share them, and on a row only when it differs), elapsed, calls and tokens with small bars, cost, errors and files edited. Three dots rate its duration, tokens and errors against the session's other subagents (green fine, amber above 1.5 times the median, red above 3 times, or over 5 minutes running, over 1M input tokens, two or more errors, or a last call that failed). The worst come first and running ones stay on top until you sort by a column. More than eight sharing a name before a colon fold into one row. Ten rows show, and every running one, the rest behind Show all. Click a row for its prompt, tokens, times and its own waterfall, with buttons to show its calls, copy a summary or show only its failures. Arrow keys move, Enter or Space open, Esc closes and `f` shows the agent's tool calls.
- **The other views:** a sortable and filterable table of tool calls, the session log with its search, and what the project's past sessions left.
- **Pane button:** the button in the top bar, or the command palette, hides or shows the pane in that Claude Code session, so the browser can take over. The session goes on as usual and the done gate still runs. `/agentmon` in the session shows the pane again.

| Key | Action |
|---|---|
| `Ctrl+K` or `⌘K` | Command palette: switch session, jump to a section, show only failures, hide the pane, change theme, copy the working directory |
| `/` | Search the session log |

Every running session on the machine shares one server. With more than one running, the working directory in the top bar becomes a switch between them. Its last entry opens [AgentMon Start](https://codenotary.com/agentmon-start), for a combined view, in a new tab. A dot and a word show each session's state: green and pulsing when it works, orange when it waits for you (an approval or a waiting subagent), grey when it is idle. The server is a small Node program inside the plugin. It starts with the first session and stops one minute after the last one leaves. A session whose plugin files are newer replaces a running server, and open tabs reload themselves. It needs `node` on your `PATH`: Claude Code does not include it. Without it the pane works as usual, there is no button, and the session shows a short notice when it starts. The debug log says why.

**Kiro Crew chats.** The server also lists every open [Kiro Crew](https://kiro.dev) chat on the machine as a session, whatever harness the chat runs on (kiro-cli, Claude Code, Codex and the others). It reads the crew log Kiro Crew writes under `~/.kiro/crew/crew-log/`, so nothing has to be installed in Kiro Crew. The top bar names such a session `Kiro Crew` and its crew.

- **What you see:** the turns with where their time went, each tool call with its duration and result, calls waiting for your approval and the time they held a turn (Blocked on you), subagents and the files they wrote, files the chat edited, the task list, the context gauge, tokens, Insights (slow calls, large results, repeated approvals), Events (approvals, failed subagents, long calls, a turn held up by approvals), and your prompts and the answers. A subagent stays under Running now until it reports back.
- **Verification:** the last test, lint, typecheck and build command the chat ran, each ok, failed or unknown, and the files edited since the last passing test run. It is read from the command and whether the call failed: Kiro Crew's log holds no output, so there are no test counts, and a pipe, `||` or a later command after `;` leaves the result unknown. A check in a subagent's chat, or past the first 300 characters of a command, is not seen.
- **What stays empty:** the done gate and learning, which come from the mod's own hooks in a Claude Code session. Cost in dollars is not shown. kiro-cli reports credits in place of tokens and cost: the Session cost tile then reads **Credits**, the chat's total, and the token numbers and Cache hit stay empty. Subagents have no token counts.
- **When it leaves:** when the chat is closed or reset in Kiro Crew, or 30 minutes after its last entry. A turn under way gets two hours, since a long tool call writes nothing.
- **A chat on the Claude Code harness** loads the mod itself and shows in full, once, under the same entry.
- **Start with Kiro Crew:** install this repo as a Kiro Crew app. The server then starts whenever Kiro Crew starts, stays up as long as it runs, and Kiro Crew gets an **AgentMon** tab in the chat side panel ("+" menu) and an **AgentMon Live** page, both showing the web view with every session.
  - From a clone: `kirocrew app install /path/to/agentmon-live`, then enable **AgentMon Live** in Kiro Crew's apps.
  - From GitHub: add `https://github.com/codenotary/agentmon-live` as a registry (Settings, Security, Trust), then install **AgentMon Live** from the store.
  - Kiro Crew asks you to trust the app before its code runs. That code is `kiro/hooks.py`, about 100 lines of standard-library Python that run inside Kiro Crew's gateway with its rights: it writes `~/.claude/agentmon-live/kiro.json` (the gateway's process id and address) and starts `node server/web.mjs ensure 47311`. Read it before you say yes.
  - It needs `node`, found on your `PATH` or under nvm, fnm, Volta or Homebrew.
  - The tab shows every session, not only the chat it sits beside: Kiro Crew does not tell an app which chat a tab belongs to. It expects the server on port 47311.
  - The tab opens on the chat beside it and follows when you switch chats, an idle or closed chat as it ended; a session you pick in its top bar stays until the next switch. The tab works on Linux and macOS, where the server can tell that the page belongs to your account.
  - Only Kiro Crew's own page may frame the web view, and only while its gateway runs. After Kiro Crew quits, the server stops a minute after its last session.
- **Without the app and with no Claude Code session open** nothing starts the server. Start it yourself: `node /path/to/agentmon-live/server/web.mjs ensure 47311`. A Kiro Crew script hook cannot: Kiro Crew runs hooks in its sandbox, which hides the crew log and has no `node` on its `PATH`.
- **Web view only:** the pane is part of Claude Code.

**Sessions in a VM or a container.** A session that cannot reach the server on your machine writes its snapshots to a folder the server reads. The mod must be installed where the session runs.

- **In the VM or container:** mount the shared folder at `/var/lib/agentmon-live/spool`. A session that finds that folder writes `<session id>.json` there and starts no server of its own. For another path, set `AGENTMON_SPOOL` in the environment Claude Code starts with. The pane's link and `/agentmon open` have no address to give there, and the page shows no pane button for such a session: nothing flows back into it.
- **On your machine:** the folder to share is `~/.claude/agentmon-live/spool`. The server reads it, or the folder in its own `AGENTMON_SPOOL`, every 2 seconds. With no Claude Code session open here, start the server yourself as above; it stays up while a session writes.
- **In the session list** such a session reads **sandbox** before its state, so you can tell it from one on your machine.
- **When it leaves:** when the session ends, or 90 seconds after its file last changed. The server removes the file.
- **What can write the folder can add a session to your page.** The server reads plain files only, follows no link, and takes at most 64 files of 4 MB. The page shows a snapshot's text as text. It does not check every field: a broken snapshot can leave the page blank until its file is gone.
- Like Kiro Crew chats, these sessions are listed only with `webToken` on.

The page only reads, with one exception: the pane button tells the session to hide or show its pane. Nothing else flows from the browser back into a session. The server listens on `127.0.0.1` only and refuses other host names and writes from web pages. Secrets are masked first, as in the pane.

Only your account uses the port (`webToken`, on by default):

- **Sessions and server.** A secret sits in `~/.claude/agentmon-live/web.token`, a file only your account can read. It is never sent. When a session starts, it and the server prove to each other that they hold it, and the session gets a key for that server run. A program of another account that takes the port, before or after, cannot give that proof: the session moves to the next port, or stops posting, and it gets no snapshot.
- **Browser on Linux and macOS.** The server asks the system which account holds the browser's end of the connection (`/proc` on Linux, `lsof` on macOS). Yours gets in: open the address, typed, bookmarked or from the pane, and type nothing. This also holds through an SSH port forward, for every account on the machine you forward from: forward the port only from a machine you do not share.
- **Browser on Windows.** The system does not say, so `o` and `/agentmon open` open an address with a one-time code, good for five minutes. The page trades it for a pass it keeps in the browser, and takes the code out of the address. The pass works until the server stops, a minute after the last session closes; then open the page again with `o` or `/agentmon open`. An address you type by hand in a browser that never had a code shows no sessions. The code is visible to other accounts for the moment the browser starts, in the list of running programs, and whoever uses it first gets in: on a shared Windows machine, set `web` to `off`.
- **`webToken: off`** turns the checks off (Kiro Crew chats then do not show: they are listed only behind the lock): any local process can then read your session's prompts, commands, paths and costs, and post to the page. A server started with the checks on keeps them until it stops, and sessions with `off` use it meanwhile.

A session still running a plugin version from before these checks cannot post to the new server: restart it.

`web`, `webPort` and `webToken` take effect at the next session start, turning `web` off as well as on. If the server does not start, the session tries again once a minute. Over SSH on Linux, a browser opens on your desktop session on that machine if you have one, such as a local or RDP login. Where no browser can open, `o` and `/agentmon open` give the address to open yourself (on macOS and Windows with its one-time code).

With no desktop session there, the server still listens on the remote machine, so forward its port from your own machine, keeping the same number, and open the address there. The server refuses a different port number in the address.

```sh
ssh -L 47311:127.0.0.1:47311 <user>@<host>
```

### Debug log

With `debugLog` on, each session writes one file: `<Claude config folder>/agentmon-live/debug/<day>/<session>.log`, the config folder being `CLAUDE_CONFIG_DIR` or `~/.claude`. Every line is a time, an event and its metadata: session start with the options, each turn, each tool call (name, time taken, denied or failed), each done-gate decision, compactions, and hook failures. Prompts, file text and command lines are never written. `/agentmon debug` prints the path of this session's file. Each file keeps the last 3000 lines. At session start the mod deletes log files not written for seven days, through `find` under that debug folder only, and then the empty day folders.

### Base branch

Every `gitPollMinutes` minutes, and after each turn that ran a git command, the mod compares the branch with its base: the remote's default branch (`origin/HEAD`), else `origin/main`. When the base has commits this branch lacks, Focus says how many. When those commits changed files the session edited, the item turns red and names them: rebase before more edits. `i` drafts a request to show what the base changed in those files, rebase and rerun the checks. By default the mod does not fetch, so the check sees the base as of your last `git fetch`. With `gitFetch` on, it fetches the base branch first (never with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` set, never asking for credentials). Outside a git repository, or without an `origin` remote, nothing shows.

### Cost

Fable is asked at most once per stop, and only when the recorded facts show no gap: one small model call (low effort, at most 300 output tokens, about 12,000 characters of material). `advisorBudget` caps the calls per session, and the pane shows Fable's own tokens. Set `advisorMode` to `gate` for no model calls at all.

### File-size guide

Big files are hard to take in, for people and for agents alike. When an Edit or Write, by the main session or a subagent, leaves a maintained source file over `sizeLimit` bytes (20,000 by default, about 5,000 tokens; a size heuristic, not a token count), Focus says so. Its `investigate` draft asks to split the file along distinct responsibilities with clear interfaces between the parts, and not to split arbitrarily or add abstractions just to get under the number. A file that was already over the limit is flagged only when it grows; a new file over the limit is flagged at once. It only warns; nothing is blocked.

Only source files count (`.ts`, `.py`, `.go`, `.rs` and the like), and only inside the project. Built-in exclusions skip lockfiles (`package-lock.json`, `yarn.lock`, `Cargo.lock`, `go.sum`, …), generated code (`*.min.*`, `*.map`, `*.generated.*`, `*.pb.go`, `generated/`), vendored code (`node_modules/`, `vendor/`, `third_party/`), build output (`dist/`, `build/`, `out/`, `target/`, `.next/`, `coverage/`) and fixtures (`fixtures/`, `__snapshots__/`, `testdata/`, `*.snap`). Add your own with `sizeExclude`.

For a file that should stay whole, add it to `.agentmon-size` at the project root, one glob per line with the reason after `#`. A line without a reason is ignored, so every exception says why:

```
src/schema.ts      # one table per type; kept together on purpose
src/legacy/*.ts    # ported code, split after the migration
```

### Test targets

In a repository with several packages, a test run only verifies the package it ran in. The mod records where each test command ran: the shell's directory, moved by a `cd` in the command, `--prefix`/`-C`, a workspace (`pnpm --filter web`, `npm -w web`, `yarn workspace web`, `cargo test -p web`) or a path argument (`go test ./api/...`, `vitest packages/api`). A name filter (`-t`, `-k`, `-run`, `--grep`) or a single test file makes the run focused. A folder written with `~` or a variable is unknown, so that run reaches no package.

Each edited source file belongs to its nearest package root (a directory with `package.json`, `pyproject.toml`, `Cargo.toml` or `go.mod`); config, lockfiles and data need no test unless a rule below names them. Every test in a chained command counts, each from its own directory. When tests ran after the last edit, every edited package needs a run in it or above it with at least one test executed; a focused run is enough. Otherwise the gate sends back `packages/api: edited (auth.ts), but no test run after the edit reached it`.

To state the expectation yourself, add `.agentmon-tests` at the project root: per line a glob of edited files, the directory whose tests cover them, optional `full` (no name or file filter allowed) and `min=N` (at least N tests executed, default 1), and a reason after `#`. A line without a reason is ignored. A declared target is expected even when no test ran at all:

```
packages/api/**   packages/api              # api unit tests
packages/core/**  packages/core  full min=20 # shared code: the whole suite
```

### Learning across sessions

At the end of each turn the mod keeps a small record of the session, per project, in its own store: tool calls and errors per tool, errors by signature (the first line, numbers and paths taken out), results of 10k+ tokens, tool calls per prompt, where the context compacted, and the MCP servers loaded. The last 30 sessions count. `/agentmon learn` fills that history from the project's past transcripts once. From it, Focus suggests; it never changes anything itself:

- **plan**: the context nears where past sessions compacted (90% of that point; with no history, 70% of the window). It names `/compact <focus>`, a lower effort when effort is high, and `/model sonnet` on a large model.
- **flaky**: a tool that failed in at least 25% of 10 or more calls over 3 or more sessions, with its last error. Its first call in a session also gives a toast.
- **unused**: an MCP server loaded in 5 or more sessions and never called, with the schema tokens it costs each time.
- **habit**: a tool that put 10k+ tokens into context 4 or more times over 3 or more sessions.
- **recurring**: the same error met in 3 or more sessions. `i` drafts a CLAUDE.md note, or a check at session start, that would save finding it again; nothing changes until you send it.
- **long turn**: this turn's tool calls are 1.25× past the 90th percentile of past turns in this project (5 past turns or more, never under 10 calls). `i` drafts a request to say what is done, what is left and whether the approach needs to change.
- **gate**: the kind of gap the done gate sent back in 3 or more sessions (failed or stale tests, an unbacked "tests pass", an edited package no test reached, a test run that ran no tests, a test run with fewer tests after the edit, open todos, failing subagent tests, parts of the request Fable found unanswered), counted from the gate's own feedback, live or in past transcripts. `i` drafts a CLAUDE.md rule that would stop it; nothing changes until you send it.
- **memory**: the memory and instruction files the session loads, plus the project's auto-memory folder, checked at start, after each edit of one and at the end of each turn (so a change by Bash, an editor or a git checkout shows too). It finds a memory name used twice, MEMORY.md entries without a file and files without an entry, backticked paths that no longer exist (a `/api/...` route whose top folder is not on disk does not count), files over about 10k tokens, instruction files over 200 lines, instruction files with 5 or more lines of `IMPORTANT`, `MUST`, `NEVER` and the like (a rule that must hold belongs in a hook or deny rule), and lines copied between files.

### Self benchmark

`/agentmon bench` puts this project's sessions without the mod, with it, and with it in the last 7 days side by side: edit prompts checked after their last edit (the last test, lint, typecheck or build of each kind passed, and a test run reached every edited package), edit prompts that edited one file 4 or more times, the tool error rate, compactions per session, the median time of a prompt that used tools, output tokens per turn, the cost per session (each request's tokens at its model's list price, main loop only; `–` when no request's model has a known price), and for the done gate how often it sent Claude back, how often more tool calls followed, how often it found nothing open, and Fable's calls. The mod records each session as it runs and keeps the last 300 per project. `/agentmon learn` adds past sessions from their transcripts; one that ran with the mod counts as with it. A column with fewer than 5 sessions shows `–`. It is a before-and-after comparison, not a controlled test, so it cannot prove cause.
